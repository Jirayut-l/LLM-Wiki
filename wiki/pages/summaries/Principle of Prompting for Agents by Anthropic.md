## 1. นิยามของคำว่า AI Agent (What is an Agent?)

- เอเจนต์คือโมเดลภาษา (LLM) ที่สามารถหยิบเอาเครื่องมือ (Tools) ต่างๆ มาใช้ในระบบการทำงานแบบวนลูป (Loop)  เมื่อคุณมอบหมายเป้าหมายสุดท้ายให้ เอเจนต์จะตัดสินใจเองว่าจะใช้เครื่องมือชิ้นไหน รับข้อมูลกลับมา คิดทบทวน และดำเนินการต่อจนกว่างานจะสำเร็จ 
- **ภาพจินตนาการ (Visualization):** ลองนึกถึง "ช่างซ่อมบ้านมืออาชีพ" ที่เราแค่บอกว่า "ช่วยซ่อมท่อน้ำที่รั่วในห้องน้ำให้หน่อย" ช่างจะเดินไปที่ห้องน้ำ (สภาพแวดล้อม) เปิดกระเป๋าเพื่อเลือกเครื่องมือ เช่น ประแจ หรือเทปพันสายไฟ ลองซ่อมดูแล้วเปิดน้ำเช็คว่ายังรั่วไหม (รับข้อมูลกลับมา) หากยังรั่วก็จะเปลี่ยนไปหยิบกาวมาทาซ้ำจนกว่าน้ำจะหยุดไหล โดยที่เราไม่ต้องไปยืนสั่งทีละก้าว

## 2. เมื่อไหร่ที่ควรและไม่ควรใช้เอเจนต์ (When to Use Agents)

- ไม่จำเป็นต้องใช้เอเจนต์กับทุกงาน ควรใช้กับงานที่มีความ **ซับซ้อนและมีมูลค่าสูง** ซึ่งมนุษย์ไม่สามารถเขียนลำดับขั้นตอน (Workflow) ที่ตายตัวล่วงหน้าได้ชัดเจนและผลกระทบจากความผิดพลาด (Cost of errors) ต้องอยู่ในระดับที่ยอมรับหรือกู้คืนระบบได้

- **ตัวอย่างการใช้งาน:**
    - **งานที่ควรใช้:** การให้ AI อ่านเอกสารออกแบบระบบ (Design Doc) แล้วไปเขียนโค้ดเพื่อเปิด Pull Request (PR) เอง เพราะขั้นตอนระหว่างทางต้องมีการลองผิดลองถูกและปรับเปลี่ยนตามสถานการณ์ หรือการทำ Data Analysis ที่ข้อมูลดิบอาจจะมาหลายรูปแบบและมีข้อผิดพลาดเยอะ
    - **งานที่ไม่ควรใช้:** งานที่สามารถกำหนดเงื่อนไข 1, 2, 3, 4 ได้ชัดเจนอยู่แล้ว (เช่น การจัดหมวดหมู่เอกสารธรรมดา) การใช้เอเจนต์จะสิ้นเปลืองทรัพยากรเกินความจำเป็น 

| **ปัจจัยพิจารณา**  | **❌ ควรใช้ Linear Workflow (Standard LLM)**      | ✅ **ควรใช้ AI Agent**                                |
| ------------------ | ------------------------------------------------ | ---------------------------------------------------- |
| **กระบวนการทำงาน** | มนุษย์รู้ขั้นตอน 1, 2, 3, 4 ชัดเจนแน่นอนอยู่แล้ว | รู้เป้าหมาย แต่ไม่รู้ขั้นตอนระหว่างทางที่แน่นอน      |
| **ความผิดพลาด**    | ข้อผิดพลาดทำให้ระบบล่มหรือเกิดความเสียหายร้ายแรง | ข้อผิดพลาดสามารถกู้คืนได้ / มีวิธีตรวจสอบย้อนกลับ    |
| **ความคุ้มค่า**    | งานทำซ้ำทั่วไป (Low Value) สิ้นเปลืองทรัพยากร    | งานสร้างมูลค่าสูง ประหยัดเวลาของวิศวกรระดับสูงได้มาก |
### ตัวอย่างสถานการณ์จริง (Use-Case Examples)

- **สถานการณ์ที่ 1: การเขียนโค้ดแก้บั๊กในโปรเจกต์ขนาดใหญ่ (ควรใช้ Agent 🧑‍💻)**
    
    - _เหตุผล:_ เรามีเป้าหมายคือ "แก้บั๊กเลขที่ #402" แต่ AI ไม่รู้ล่วงหน้าว่าไฟล์ไหนเสีย มันต้องเข้าไปหาไฟล์ อ่านโค้ด ทดสอบรันคำสั่ง Bash ดู Error Message แก้ไขโค้ด แล้วรันเทสซ้ำๆ จนกว่าจะผ่าน (กระบวนการมีลองผิดลองถูกและซับซ้อน)

- **สถานการณ์ที่ 2: การออกใบเสร็จและจัดหมวดหมู่ประเภทค่าใช้จ่าย (ไม่ควรใช้ Agent 📄)**
    
    - _เหตุผล:_ สามารถเขียนสคริปต์แบบ Linear หรือ Rule-based ผสมโครงสร้าง Prompt ปกติได้ เช่น: ดึงยอดเงิน -> ดึงชื่อร้าน -> ส่งให้ LLM แยกประเภท -> บันทึกลงฐานข้อมูล จบในขั้นตอนเดียว ไม่จำเป็นต้องรัน Loop ให้เปลืองทรัพยากร

## 3. หลักการคิดแบบเอเจนต์และการใส่หลักเกณฑ์การตัดสินใจ (Think Like Your Agents & Heuristics)

- ผู้พัฒนาต้องมี Mental Model หรือเข้าใจสภาพแวดล้อมที่เอเจนต์อยู่ การพ่นคำสั่งยาวๆ ใส่ Prompt แบบเดิมใช้ไม่ได้ผลดีกับเอเจนต์ แต่เราต้องใส่ **แนวคิด (Concepts) และหลักการตัดสินใจ  [[#Heuristics]]  ลงไป 

- **ตัวอย่างและวิธีการ:**
    - **กฎการไม่ทำลายล้าง (Irreversibility):** สั่งเอเจนต์อย่างชัดเจนว่า "ห้ามทำแอคชันใดๆ ที่ไม่สามารถกู้คืนกลับมาได้" เช่น ลบฐานข้อมูลถาวร หรือการทำลายสภาพแวดล้อมของผู้ใช้
    - **การตั้งงบประมาณและจุดหยุดทำงาน (Budgets & Stopping Thresholds):** ปัญหาที่พบบ่อยคือ เอเจนต์จะค้นหาข้อมูลไปเรื่อยๆ ไม่มีวันสิ้นสุดแม้ว่าจะเจอคำตอบแล้ว ดังนั้นต้องเขียนสั่งให้ชัดเจนว่า "เมื่อเจอคำตอบที่ต้องการแล้วให้หยุดทำงานทันที"หรือกำหนดว่า "งานทั่วไปให้ใช้ Tool Call ไม่เกิน 5 ครั้ง งานยากไม่เกิน 10-15 ครั้ง"
    - **เปรียบเทียบคำแนะนำ:** ให้คิดว่าคุณกำลังสอนงาน "เด็กฝึกงานที่เพิ่งเรียนจบ"คุณไม่ได้บอกให้เขาพิมพ์คีย์บอร์ดทีละปุ่ม แต่คุณต้องสอน "หลักคิดการทำงานและขอบเขตที่ทำได้" เพื่อให้เขาไปตัดสินใจหน้างานเองได้ถูกต้อง

#### 🧠 วิธีคิดแบบ "สอนเด็กฝึกงานใหม่ (The Intern Analogy)"

ให้จินตนาการว่าคุณกำลังสอนงาน **"เด็กฝึกงานที่เพิ่งเรียนจบใหม่และยังไม่เคยทำงานที่ไหนเลย"** คุณไม่สามารถบอกให้เขาขยับมือนิ้วไหนพิมพ์อะไร แต่คุณต้องให้ "หลักการคิดกว้างๆ และกรอบความปลอดภัย" เพื่อให้เขาไปเผชิญหน้ากับงานเอง

#### 💡 ตัวอย่างการใส่ Heuristics (หลักการตัดสินใจ) ใน System Prompt

```Markdown
# SYSTEM PROMPT EXAMPLE FOR RESEARCH AGENT

## 1. Core Principles & Heuristics
- **Stopping Threshold:** คุณมีเป้าหมายค้นหาข้อมูลที่ลึกซึ้ง เมื่อใดก็ตามที่คุณพบ "หลักฐานและคำตอบที่ชัดเจนเพียงพอแล้ว" ให้หยุดเรียกใช้เครื่องมือค้นหาทันที ห้ามรัน Loop ซ้ำเพื่อหาข้อมูลเดิม
- **Irreversibility Avoidance:** ห้ามทำคำสั่งใดๆ ที่มีผลถาวรและไม่สามารถย้อนกลับได้ (เช่น การลบไฟล์หรืออัปเดตฐานข้อมูลหลัก) หากจำเป็นต้องทำ ให้หยุดทำงานและขอการยืนยันจากมนุษย์ (Human-in-the-loop) เสมอ
- **Token Budgeting:** สำหรับคำถามทั่วไป ให้จำกัดการเรียกเครื่องมือ (Tool Calls) ไม่เกิน 5 ครั้ง หากเป็นโจทย์วิเคราะห์เชิงลึก สามารถใช้ได้สูงสุด 15 ครั้ง
```

## 4. การจัดการบริบทและเทคนิคขั้นสูง (Context Window & Sub-agents)

- แม้โมเดลยุคใหม่อย่าง Claude 4 จะมี Context Window ที่ใหญ่มาก (200k tokens)  แต่การให้เอเจนต์ทำงานอิสระเป็นเวลานานอาจทำให้ Token เต็มได้ จึงต้องใช้เทคนิคการจัดการบริบทเข้ามาช่วย 
### 💡 เทคนิคการจัดการบริบท (Advanced Strategies)

#### 🔄 1. Compaction (การบีบอัดหน่วยความจำ)

เมื่อปริมาณการคุยและ Log ของเครื่องมือใกล้ถึงขีดจำกัด (เช่น แตะ 190,000 Tokens) ให้ระบบกระตุ้นเอเจนต์ให้เรียกใช้ Tool สรุปประวัติทั้งหมดให้เหลือเพียงสาระสำคัญที่หนาแน่น (Dense Summary) แล้วส่งต่อสรุปนี้เข้าสู่ Session ใหม่ วิธีนี้เสมือนการ "ล้างสมองส่วนที่รกและจำเฉพาะใจความสำคัญ" ทำให้เอเจนต์รันต่อได้ไม่มีวันสิ้นสุด
	- (คือเหมือนให้ agent compress work ที่ทำอยู่ และสรุปออกมาและเอาที่สรุปออกมาไปส่งให้ ตัวใหม่ทำงานต่อ) 

#### 👥 2. Multi-Agent Systems (ระบบเอเจนต์ย่อย)

แทนที่จะใช้เอเจนต์ตัวเดียวทำทุกอย่าง ซึ่งจะทำให้ Context บวมเร็วมาก ให้เปลี่ยนมาใช้โครงสร้างแบ่งแยกหน้าที่ (Separation of Concerns)
- **Lead Agent:** ทำหน้าที่วางแผนภาพรวม คุยกับผู้ใช้ และจัดทำรายงานสรุปสุดท้าย
- **Sub-Agents (Workers):** เอเจนต์เฉพาะทาง เช่น ไปรัน Web Search ค้นหาข้อมูลอย่างบ้าคลั่ง เมื่อเสร็จแล้วทำการสรุปข้อมูลสั้นๆ ส่งกลับให้ Lead Agent (Context ของข้อมูลขยะจากการค้นหาจะถูกทำลายทิ้งไปพร้อมกับ Sub-agent)

## 5. การประเมินผลเอเจนต์ (Agentic Evaluations)

- **สรุปจากวิดีโอ:** การทำ Evaluation สำหรับเอเจนต์นั้นทำยากกว่าโมเดลทั่วไป เพราะเอเจนต์มีพฤติกรรมที่ไม่ตายตัวคำแนะนำคือ **ให้เริ่มจากชุดทดสอบขนาดเล็กๆ ก่อน (Small Eval)** ไม่จำเป็นต้องทำระบบ Automation ขนาดใหญ่ตั้งแต่แรก

### 💡 รูปแบบการตั้ง Eval สำหรับเอเจนต์ (Examples)

#### 🟩 รูปแบบที่ 1: LLM as a Judge (ใช้ AI ตรวจสอบโดยมีเกณฑ์ล่วงหน้า)

เนื่องจากผลลัพธ์ของเอเจนต์มักเป็นข้อความขนาดยาวที่มีรูปแบบไม่ตายตัว การใช้สคริปต์ตรวจความถูกต้องแบบ String Matching ปกติจะพังได้ง่าย จึงใช้โมเดลระดับท็อปอีกตัวมาเป็นกรรมการตรวจแทน

- _ตัวอย่างพรอมต์ของกรรมการ (Judge Prompt):_
```md
คุณมีหน้าที่ตรวจรายงานของเอเจนต์วิเคราะห์รถยนต์ จงให้คะแนน Pass หรือ Fail ตามเกณฑ์ต่อไปนี้: 1. รายงานต้องมีการประเมินปริมาณความจุของรถ Rivian R1S 2. ตัวเลขการคำนวณจำนวนกล้วยที่ใส่ได้ ต้องอยู่ระหว่าง 10,000 ถึง 50,000 ผลเท่านั้น (หากต่ำกว่าหรือสูงกว่านี้ให้ Fail) 3. มีการระบุแหล่งอ้างอิงที่น่าเชื่อถืออย่างน้อย 2 แหล่ง
```

#### 🟩 รูปแบบที่ 2: Tool Use Accuracy (ตรวจสอบพฤติกรรมการเรียกใช้เครื่องมือ)

เขียนโปรแกรมเช็คจากประวัติการทำงาน (Execution Logs) โดยตรง เพื่อควบคุมพฤติกรรมเอเจนต์

- _ตัวอย่างเกณฑ์:_ หากผู้ใช้สั่งให้ "จองตั๋วเครื่องบินข้ามประเทศ" -> สคริปต์หลังบ้านต้องตรวจเจอการเรียกใช้ฟังก์ชัน `search_flights` อย่างน้อย 1 ครั้ง และต้องไม่มีการเรียกใช้ฟังก์ชัน `confirm_payment` จนกว่าจะได้รับข้อมูลไฟลท์บินเรียบร้อยแล้ว

#### 🟩 รูปแบบที่ 3: State-based Evaluation (การตรวจสอบสถานะสุดท้ายของระบบ)

วิธีที่แม่นยำที่สุดสำหรับงานวิศวกรรมซอฟต์แวร์ คือการไม่สนใจสิ่งที่เอเจนต์อธิบายระหว่างทาง แต่ตรวจสอบ **"ผลลัพธ์สุดท้ายในโลกความเป็นจริง (Final State Change)"** เช่น ในโปรเจกต์โอเพนซอร์สอย่าง ToBench

## Heuristics

ในทาง AI** คือ "หลักการคิดกว้างๆ" หรือ "สูตรทางลัดในการตัดสินใจ" ที่ช่วยให้ AI สามารถแก้ปัญหาที่ซับซ้อนได้อย่างรวดเร็ว โดยไม่จำเป็นต้องคำนวณหรือค้นหาทุกความเป็นไปได้ในโลก ซึ่งถ้าเปรียบเทียบกับการเขียนโปรแกรมทั่วไป Heuristics ก็คือการเปลี่ยนจากการใช้ brute-force algorithm มาเป็นการใช้ "กฎเกณฑ์ที่สมเหตุสมผล" เพื่อตัดตัวเลือกที่ไม่จำเป็นออกไปครับ
เพื่อให้เห็นภาพชัดเจนและสอดคล้องกับบริบทของ **AI Agents** จากวิดีโอของ Anthropic ที่เราดูก่อนหน้านี้ เราสามารถแบ่งคำว่า Heuristics ในโลกของ AI ออกเป็น 2 ยุคหลักๆ ดังนี้ครับ:

### 1. Heuristics ในยุค Agent สมัยใหม่ (LLM-based Agents)

ในยุคของ Generative AI และ AI Agents คำว่า Heuristics จะหมายถึง "หลักคิด หรือกรอบพฤติกรรมหน้างาน"ที่เราป้อนใส่เข้าไปใน System Prompt เพื่อเป็นเข็มทิศให้ AI รู้ว่าในสถานการณ์ที่คาดเดไม่ได้ ควรจะตัดสินใจเลือกทำแอคชันอย่างไรให้สมเหตุสมผลและปลอดภัย

- **ตัวอย่างเปรียบเทียบ (Analogy):** เหมือนเวลาคุณตั้มสอนงาน **"เด็กฝึกงานใหม่"** คุณไม่ได้บอกให้เขาพิมพ์คีย์บอร์ดคำไหน หรือคลิกเมาส์พิกเซลไหน (เพราะหน้างานจริงเปลี่ยนไปเรื่อยๆ) แต่คุณจะให้หลักคิดกว้างๆ เช่น _"ถ้าลูกค้าบ่นว่าระบบล่ม ให้กู้ระบบคืนก่อนเรื่องอื่นเสมอ"_ หรือ _"ถ้าหาข้อมูลเกิน 3 แหล่งแล้วยังไม่เจอคำตอบ ให้หยุดหาแล้วเดินมาถามพี่"_
    
- **ตัวอย่าง Heuristics ใน Prompt ของ Agent จริงๆ:**
    
    - **Irreversibility Heuristic:** _"ถ้าต้องรันคำสั่งที่มีผลถาวรและย้อนกลับไม่ได้ (เช่น `DROP DATABASE`) ให้หยุดทำงานและขอคอนเฟิร์มจากมนุษย์ก่อนเสมอ"_
        
    - **Stopping Heuristic:** _"เมื่อไหร่ที่ค้นหาเว็บแล้วเจอตัวเลขสถิติที่ต้องการครบถ้วนแล้ว ให้หยุดเรียกใช้ Tool ค้นหาทันที เพื่อประหยัด Token"_

### 2. Heuristics ในยุค AI ดั้งเดิม (Traditional AI & Algorithms)

หากย้อนกลับไปในวิชา Computer Science หรือ AI ยุคคลาสสิก Heuristics จะอยู่ในรูปของ **Mathematical Function (h(x))** ที่ใช้ประเมินความน่าจะเป็นเพื่อนำทางตัว Search Algorithm ให้เดินไปหาเป้าหมายได้เร็วที่สุด โดยไม่ต้องสุ่มเดินมั่วๆ

- **ตัวอย่างคลาสสิก (Pathfinding):** สมมติว่าเรากำลังเขียนอัลกอริทึมให้ AI หาทางเดินในเขาวงกตเพื่อไปยังจุดหมาย (Goal)
    
    - **แบบไม่มี Heuristics (Brute-Force / BFS):** AI จะต้องลองเดินไปทุกๆ ทางแยกที่มีในแผนที่ ตรวจสอบทุกตารางนิ้วจนกว่าจะเจอทางออก ซึ่งใช้พลังงานและเวลา Compute มหาศาล
        
    - **แบบมี Heuristics (A∗ Search Algorithm):** เราใส่ Heuristic Function เข้าไป เช่น การคำนวณ **"ระยะห่างแบบเส้นตรง (Euclidean Distance)"** จากจุดที่ AI ยืนอยู่ไปยังจุดหมายปลายทาง แม้ระหว่างทางจะมีกำแพงกั้น แต่ AI จะเลือกเดินเข้าหาทิศทางที่ทำให้ระยะเส้นตรงนี้ "สั้นลง" เสมอ ทำให้มันสามารถตัดเส้นทางฝั่งตรงข้ามที่ไม่เกี่ยวข้องทิ้งไปได้เกือบทั้งหมด

## สรุปข้อดีและข้อจำกัดของ Heuristics

### 🟩 ข้อดี:

1. **Speed & Efficiency:** ช่วยลดปริมาณการคำนวณและการเรียกใช้เครื่องมือ (Tool Calls) ได้อย่างมหาศาล ทำงานเสร็จไวขึ้น
2. **Handle Ambiguity:** ช่วยให้ AI สามารถเอาตัวรอดและตัดสินใจในสถานการณ์ที่ข้อมูลไม่ครบถ้วน หรือไม่มีสูตรคำนวณตายตัวได้ดี

### 🟥 ข้อจำกัด (Trade-off):

- **Not Guaranteed to be Optimal:** คำตอบที่ได้จาก Heuristics อาจจะ **ไม่ใช่คำตอบที่ดีที่สุด 100% (Not Best)** แต่มันคือ **"คำตอบที่ดียอดเยี่ยมและทันเวลาพอที่จะใช้งานได้ (Good Enough & Fast)"**
