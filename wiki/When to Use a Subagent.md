# When to Use a Subagent

## Summary
แนวทางปฏิบัติและเงื่อนไขที่ช่วยตัดสินใจว่าสถานการณ์ใดเหมาะสมที่จะเรียกใช้งาน Subagent และสถานการณ์ใดที่ควรหลีกเลี่ยง

## Core Content
- **คำถามหลัก (Rule of Thumb):** 
  - *"งานนี้กำลังจะเทข้อมูลมหาศาลลงในแชทที่ฉันจะไม่มีวันกลับมาอ่านอีกใช่ไหม?"* 
  - ถ้าคำตอบคือ **ใช่** ให้ใช้ Subagent ทันที เพื่อป้องกันการเกิดขยะ (Pollution) ใน Context ของ Main Session

- **สัญญาณที่บอกว่าควรใช้ (When to Use):**
  - เมื่อต้องอ่านและค้นหาข้อมูลจากไฟล์จำนวนมาก 
  - เมื่องานนั้นจะให้คำตอบยาวเป็นกำแพงข้อความ (Wall of output)
  - เมื่อเป็นงานซ้ำๆ เดิมๆ (สร้างเป็น Custom subagent ไว้ใช้เลย)
  - เมื่อมีงานหลายชิ้นที่แยกอิสระจากกัน (เช่น ตรวจสอบหนังสือ 15 บทพร้อมๆ กัน)
  - เมื่อต้องการ "Unbiased Reviewer" หรือผู้ตรวจทานที่เป็นกลาง (ตื่นขึ้นมาแบบไม่มี Memory หรือบริบทแวดล้อมเดิม)

- **สัญญาณที่บอกว่าไม่ควรใช้ (When NOT to Use):**
  - เมื่อเป็นงานแก้ไขโค้ดง่ายๆ เพียงเล็กน้อย (Quick Edit)
  - เมื่องานต้องทำเรียงลำดับขั้นตอน (Step 1 -> 2 -> 3) หรือ Agent ต้องคุยกันเอง (Subagent คุยกันเองไม่ได้)
  - เมื่อต้องใช้บริบททั้งหมดของการสนทนาใน Main Session อย่างเต็มที่

### Decision Matrix (ตารางตัดสินใจ)
| สถานการณ์ (Scenario) | ควรใช้ Subagent หรือไม่? | เหตุผล (Reason) |
| :--- | :---: | :--- |
| **อ่านไฟล์เยอะๆ หรือสรุปรายงาน 300 หน้า** | ✅ ควรใช้ | ป้องกัน Context ขยะใน Main session และประหยัดค่าใช้จ่ายได้ |
| **งานอิสระหลายๆ ชิ้น (เช่น ตรวจเอกสาร 15 บท)** | ✅ ควรใช้ | สามารถทำงานแบบขนาน (Parallel) เพื่อความรวดเร็ว |
| **ต้องการคนตรวจทานแบบเป็นกลาง (Unbiased)** | ✅ ควรใช้ | Subagent เริ่มต้น Session ใหม่โดยไม่มี Memory หรืออคติจากแชทเดิม |
| **งานที่ต้องทำตามลำดับ (1 ➡️ 2 ➡️ 3)** | ❌ ไม่ควรใช้ | Subagent คุยและส่งต่องานกันเองไม่ได้โดยตรง (ควรพิจารณา Agent Teams แทน) |
| **แก้ไขโค้ดหรือ Typo เพียงเล็กน้อย** | ❌ ไม่ควรใช้ | เสียเวลาและไม่คุ้มค่า Overhead |
